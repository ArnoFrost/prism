# Prism 3.2 Controlled Pilot

> 面向 3-5 位同事的受控试用说明。它不是 GA、production-ready 或外部稳定性背书；只验证当前 3.2 按需治理闭环是否能被未参与设计的人顺利发现、安装、试用和反馈。

## Baseline

| 项 | 值 |
|---|---|
| Pilot tag | `v3.2.0-pilot.1` |
| 来源分支 | `v3.2-clarify` |
| VERSION | `v3.2.0` |
| 验证日期 | 2026-08-01 |

Pilot 使用不可变 tag 作为安装基线；本文档不预写 commit SHA。反馈时请附带本机 `git rev-parse HEAD` 输出。

## 安装

```bash
git clone --branch v3.2.0-pilot.1 git@github.com:ArnoFrost/prism.git ~/prism
cd ~/prism
git rev-parse HEAD
cat VERSION
./setup.sh init
prism --version
```

预期：

- `git rev-parse HEAD` 输出非空 commit SHA；反馈时请原样附上。
- `cat VERSION` 输出 `v3.2.0`。
- `./setup.sh init` 完成默认本地 Workspace backend 初始化。
- `prism --version` 输出非空版本号。

## 最小体验路径

选择一个真实但可回滚的任务：最好是你自己的文档整理、需求边界收敛、代码修改前校准或跨会话接续问题。不要用生产紧急事故、权限敏感数据或不可逆发布操作做首轮试用。

建议按下面的最小路径体验：

```text
遇到新需求或不确定归属 → /workflow-intake
边界已被接受后 → /workflow-scope
下一步被一个人类取舍卡住 → /workflow-clarify
需要多视角里程碑判断 → /workflow-review
已有唯一获权目标需要推进 → /workflow-execute
想看当前状态 → /workflow-status
```

Clarify 是 3.2 的新 sidecar：它默认零写盘，只问一个会阻塞下一阶段的人类取舍；它不替代 Intake、Review、Decision 或 Scope。

Review Lite 仅为 retired-with-compat：旧 topic 或显式 legacy 调用仍可读，但日常小改默认用模型原生自检，阻塞歧义用 Clarify，需要持久多视角判断再用 Review。

## 恢复实验

试用中断后，重新打开同一项目：

```bash
cd ~/prism
prism status --project PRISM
```

如果你是在自己的项目里接入 Prism，优先看该项目的 `workspace.{code}.local/focus.md` 和 `scope.md`。恢复时请记录：

- 是否能看懂当前态与下一步；
- 是否知道该调用哪个 skill；
- 是否有旧术语、旧流程或 Review Lite 入口造成误导。

## 退出与回滚

停止试用无需删除 workspace；本轮更关注恢复体验。若只是退出试用，保留 `~/prism` 和 workspace 状态即可。

如果要清理本机实验痕迹：

- 删除测试用 clone 或测试项目中的 `workspace.*.local` 软链接；
- 保留或手动删除本地 Workspace backend；
- 不要删除团队共享仓库中的真实文件，除非你确定那是本轮试用临时创建的内容。

## Readiness Gate

邀请同事前必须满足：

- Pilot 指南可按顺序执行；
- README / onboarding / skill taxonomy / catalog 口径一致；
- setup / relink / pytest / 定向合同测试有真实结果；
- 未验证平台明确标记 `NOT VERIFIED`；
- 最终输出单一 recommendation：`PILOT` / `DEFER` / `NO-GO`。
