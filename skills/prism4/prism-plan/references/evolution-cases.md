# Plan 演进验收案例

供维护者检查关系选择；不是运行时必读或自动执行流程。合同测试仅保护指导文本，不能代替真实 Agent 行为评测。

每例要求回答：是否落盘、原地修订还是新建、旧 Plan 是否仍 current，以及依据。不得只判断编号。

| Case | 输入 | 期望 | 禁止行为 |
|------|------|------|----------|
| E1 等价复用 | 已有 Plan 完整覆盖需求，用户只问下一步 | 引用现有 Plan，不写新文件 | 为同步生成新编号 |
| E2 同目标追加 | 当前 Plan 已实现开关命中路径，新增同一路径的过渡增强，用户要求维护计划；可局部改写 | 原地修订阶段与验收，保留未命中回归约束 | 将旧 Plan 缩写成仅负责未命中路径，再声明兄弟 |
| E3 整体替代 | 用户授权新的目标边界，原行动模型需整体重写，要求保留历史 | 先修订 Intent，再新建 Plan 并显式 supersedes，承接有效基线与理由 | 因旧实现仍被复用就让两版执行口径继续 current |
| E4 合法兄弟 | 在线查询优化仍在执行，新增独立离线导出；无重叠改动与验收，各自独立接受 | 允许兄弟并存，写明互斥范围与独立验收，无 supersedes | 强制一个 Topic 只能有一个 Plan |
| E5 已实施基线 | 旧 Plan 标注待执行，但用户确认已实施；当前增强仍服务同一目标 | 授权范围内校准原 Plan 状态并追加增强；若整体重写则显式替代 | 将旧 Plan 作为兜底永久 current 或复制旧待办 |
| E6 仅跨会话 | 路线未变，即将交接，阶段状态需恢复 | 原地更新 recovery snapshot | 把跨 session 当成必须新增文件的理由 |
| E7 边界未授权 | 新需求改变 Intent 的非目标，人类未确认 | 暴露边界 gate，不以新 Plan 绕过授权 | 新建兄弟 Plan 偷扩范围 |
| E8 伪正交 | 两计划名称不同、都修改同一展示门槛且成功信号互相覆盖 | 收敛为同一行动模型，按是否需整体重写选择修订或替代 | 仅凭标题或范围声明判定正交 |

验收方式：对每例核对动作、current set、保留理由与 authority 边界。E3 与 E4 必须同时通过，防止把治理退化成禁止新编号或禁止多 Plan。行为评测需另行实际运行并记录结果，不得把文本存在性测试报告为模型行为通过。
